# Agent Skills portability

Chara's Toolkit's 22 SKILL.md folders use the open Agent Skills format. Read-only references and per-skill tools can be reused by any compatible agent with the appropriate language/runtime installed.

## Full setup for every agent

`chara setup` (or `npx --yes github:cmdr-chara/chara-toolkit setup`) installs all skills into each agent's user-level skills folder:

| `--agents` id | Agent | Skills folder |
| --- | --- | --- |
| `agents` (also `codex`, `cline`, `warp`, `zed`, `pi`) | The shared standard, read by Codex, Cline, Warp, Zed, Pi, and others | `~/.agents/skills` |
| `claude-code` | Claude Code | `~/.claude/skills` |
| `cursor` | Cursor | `~/.cursor/skills` |
| `gemini-cli` | Gemini CLI | `~/.gemini/skills` |
| `github-copilot` | GitHub Copilot | `~/.copilot/skills` |
| `opencode` | OpenCode | `~/.config/opencode/skills` |
| `windsurf` | Windsurf | `~/.codeium/windsurf/skills` |
| `droid` | Factory Droid | `~/.factory/skills` |
| `kiro-cli` | Kiro CLI | `~/.kiro/skills` |
| `roo` | Roo Code | `~/.roo/skills` |
| `goose` | Goose | `~/.config/goose/skills` |

Folders follow each agent's documented global skills path as listed by the open skills CLI (checked 2026-10-25). With the default `--agents auto`, setup always installs the shared standard folder and adds every agent whose home folder (for example `~/.claude`) exists. Pass a comma list to choose exactly, for example `--agents claude-code,cursor`.

Mission Control's six roles are defined once as neutral role cards in `skills/delegate-with-mission-cards/references/roles/`. `scripts/build_mission_control.mjs` generates native subagent files from them: Codex TOML (`~/.codex/agents`), Claude Code Markdown (`~/.claude/agents`), and Gemini CLI Markdown (`~/.gemini/agents`); setup installs each where that agent is present. Every other agent uses the role cards through the delegation skill, by giving them to a generic subagent or following them in the main session. Read-only roles are enforced by a tool allowlist in Claude Code and Gemini CLI; Codex ignores `sandbox_mode` in custom agent files, so there and elsewhere read-only is an instruction.

The Codex integration (Mission Control TOML roles, the managed `AGENTS.md` block, and the workflow catalog) is installed only when Codex is targeted: `--agents codex`, an explicit `CODEX_HOME`/`--codex-home`, a Codex home with its own files, or no other agent found.

Earlier releases installed skills into `$CODEX_HOME/skills`, which Codex now treats as deprecated. Codex does not merge the two folders, so setup moves the toolkit's copies from there into `$CODEX_HOME/backups/` and leaves skills you created yourself in place.

## Selected skills only

To install just a few skills, use the open skills CLI:

    npx skills add https://github.com/cmdr-chara/chara-toolkit --list
    npx skills add https://github.com/cmdr-chara/chara-toolkit --skill repository-intelligence --agent claude-code
    npx skills add https://github.com/cmdr-chara/chara-toolkit --skill verification-and-release --agent cursor

Verify the installed target directory and runtime support: CLI adapters, hook protocols, permission models, and discovery vary. Do not claim that a role's restrictions or the Codex-only behavioral capture runner apply in a client that does not enforce them.

Project-local skill recipes generated by scripts/project-verification.mjs also use standard SKILL.md files. A user may copy their reviewed generated folder to their client's supported project-skill directory; do not assume that every runtime automatically scans .agents/skills.

References: https://agentskills.io/specification and https://github.com/vercel-labs/skills
